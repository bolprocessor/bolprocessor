2026-03-22 (version 3.3.15)
Terminals that are defined in the alphabet, but not in a sound-object file, will no longer be deleted. Instead, they are converted to silent sound-objects, i.e. sound objects containing neither MIDI nor Csound code. Silent sound-objects have properties similar to those of simple notes. They are displayed in hatched rectangles.
Any leftover variables are no longer deleted at the end of the production or when reading BP data. Instead, they are also converted into silent sound-objects.
Consequently, the variable 'Y' appears as silences in the derivations of "-gr.koto3", but this has little effect on the sound rendering.
Check "-da.trySilentSoundObjects" for a demo.
These silent sound-objects will be used in the WebAssembly environment to connect the Bol Processor to a wide range of sound devices, including SuperCollider.
Read: https://roomi-fields.com/en/articles/bpscript-under-the-hood-architecture/
A problem with locating out-time objects has been fixed.
cJSON.c has been updated.

2026-01-10 (version 3.3.11)
Problems relating to MIDI switches #64 to #69 have been fixed.
The approach of controlling the hold pedal (#64) separately has been abandoned.
A new option, PedalReleaseDefault, has been set to true by default for switches #64 to #69. This can be changed in the project settings. If a switch is 'on' and a _switchon() control is found, the switch is first set to 'off' and then 'on' again. This is useful for controlling pedals on keyboard instruments.

2025-03-11 (version 3.3.0)
First version with "live coding" features in the "Improvize" mode (grammars only).
If "Follow grammar(s)" and/or "Follow settings" is checked in the LIVE CODING section of the settings, the console will reload a grammar, alphabet and settings taken from locations recorded in a "live" folder associated with the session. Thus, if a different grammar is saved during the performance, the console will switch to that grammar after the current variation has been played. This feature works with any number of competing grammars. There is still some work to be done in order to avoid an interruption if an invalid grammar is loaded.
Read  https://bolprocessor.org/live-coding/

2025-01-23 (version 3.2.0)
We now have a control over NoteOn/Noteoff to prevent unnecessary pairs being created when the same note/channel is turned on at the same time, as can happen when interpreting MusicXML scores. This might have been noticeable on some MIDI instruments or when capturing MIDI events.
The new procedure takes into account fast movements where the order of the notes must be maintained, even if (due to quantization) they end up with identical times.
A “Trace NoteOn/NoteOff” setting can be used to check this process.
More information: https://bolprocessor.org/control-noteon-noteoff/
A number of PHP lines have been fixed to be in compliance with PHP version 8 requirements.
Download/Upload features have been installed on Grammar and Data pages.
The “html-midi-player” MIDI file player has been replaced by “MIDIjs”, as it does not handle continuous parameters (pitchbend, pressure, etc.). This option can be changed in lines 38-39 of “_basic_tasks.php”.
Calls to mb_convert_encoding() have been added to allow reading old MacOS or Windows data/grammar files.

2024-08-20 (version 3.0.6)
😀 This is the first version of BP3 to deal with microtonality in real time MIDI. This is achieved by using scales stored in "-to" tonality files, already used by Csound. It mimics the MIDI Polyphonic Expression (MPE) method of modifying pitchbend values on notes distributed on separate channels (up to 15 simultaneous notes). However, it works on devices that are not MPE-compliant. They should only be sensitive to pitchbend messages.
Test the operation with "-da.tryMPE"
While waiting for a MIDI event, the computer can retune any incoming NoteOn/NoteOff to a tonal scale and send it to the output.
• The diapason of the external MIDI device is tried to be adjusted if it is different from 440 Hz. (Not all devices support this.)
• A backup of the previous version is created when a data or grammar project is saved.

2024-06-13
The prefixes and suffixes of some files have been changed to make them more meaningful:
• Prefix "-ho" and suffix "bpho" are replaced by "-al" and "bpal" (Alphabet files)
• Prefix "-mi" and suffix "bpmi" are replaced by "-so" and "bpso" (Sound-object files)
These changes are automatically managed by the interface and by the console.
The old prefixes/suffixes were used to denote homomorphisms and MIDI codes. Alphabet files may still contain homomorphisms but this doesn't need to be emphasised. Sound-objects can now contain Csound scores in addition to, or instead of, MIDI codes.

A (very small) dummy application called "MIDItest" has been designed to check MIDI output on the three platforms. Its source code "MIDItest.c" is provided so that Linux/Windows testers can suggest modifications to make it work as expected.

Real-time MIDI uses CoreMIDI on MacOS, ALSA on Linux and MinGW on Windows. More information on this page (which you can help to improve):
https://bolprocessor.org/check-bp3/#compile-bp-and-check-its-operation
