Bol Processor BP3 To Do List
============================

This is a list of technical improvements considered during the development of BP3. 
None of them are critical to its proper functioning. 
🎹 However, we most urgently need good musical examples to highlight BP3's features! 🎶

The most requested improvements are listed at the top of the list.

Current location of this file:
https://github.com/bolprocessor/bolprocessor/blob/graphics-for-BP3/BP3-To-Do.txt

You can also check the history of changes:
https://raw.githubusercontent.com/bolprocessor/bolprocessor/graphics-for-BP3/BP3-changes.txt

If you are interested in taking part in this project, join the BP developer's list:
https://sourceforge.net/projects/bolprocessor/lists/bolprocessor-devel


AI development
--------------

- A transformer could be trained to "understand" Bol Processor syntax. Start with polymetric notation using sample sets created with large items of "real music". These sets are matching every polymetric structure with its interpretation as a MIDIfile and a table of MIDI events. Read https://bolprocessor.org/ai-recognition-of-polymetric-notation/
- An AI tool could also conduct an in-depth analysis and documentation of the C code in ‘Polymetric.c’ and ‘Timeset.c’, as well as the literature describing these processes.


Live coding
-----------

- When loading a grammar, if the grammar is not valid, the improvisation will stop. It should continue with the previous grammar. Perhaps store a backup of the current grammar so that it can be reloaded if necessary.
- Create an option to react to changes only at the moment when an entire element has been sent to MIDI. We can use the MIDI event (ActiveSensing) at the end of each item to do this.


Realistic performance models
----------------------------

- Check the synthesis through neural codec language modelling (MIDI-VALLEE, https://tangjjbetsy.github.io/MIDI-VALLE/) to replace 'descriptive' performance controls imbedded in MusicXML scores. Mainly check that MIDI-VALLEE would not modify the microtonal instructions carried by Pitchbend instructions on separate MIDI channels.


Apache autostart in XAMPP for MacOS
-----------------------------------

- This is of minor interest due to the availability of the "BolProcessor.app" standalone MacOS application 
- The method described on https://github.com/erwinagpasa/Launching-XAMPP-at-OSX-startup is not entirely satisfactory. It allows XAMPP to restart Apache at boot time and PHP pages are displayed correctly. However, when real-time MIDI is used, MIDIClientCreate() returns an error.
- The only way to use XAMPP on MacOS is to start Apache from the Application Manager "manager-osx.app" (in XAMPP/xamppfiles).
- If the XAMPP Apache is restarted in the MacOS installation script, it runs correctly. But it is not possible to restart it in the console because "/Applications/XAMPP/xamppfiles/xampp restartapache" has to be called by 'root'.
- We hope to fix this in a forthcoming version of XAMPP.
- If the "bolprocessor" folder is relocated, using XAMPP with MacOS, it no longer works after a reboot and BP3 needs to be reinstalled. See https://bolprocessor.org/quick-install-macos/#relocating-bolprocessor


Microtonal scales and tuning systems
------------------------------------

- Tuning the MIDI device to diapason A4 ≠ 440 Hz does not work or makes a mess (e.g. Windows 10, Microsoft GS Wavetable Synth).
- Check that setting pitchbend range to ± 200 cents on all channels works.
- Include values for optional stretching of octaves.
- Implement a performance control to set the A4 frequency (diapason) within the score.

Images
------

- In Graphic.c, in the Improvize mode, dates on the ruler are adjusted by the "shift" variable. This doesn't yet work on the "pianoroll" type, because its background is drawn before updating PianorollShift. This can be solved (if felt necessary) by drawing the pianoroll graph after the completion of MakeSound, i.e. when calling DrawItem(). To this effect, the drawings of notes would be stored in a structure.
- When no settings file is specified, allow the creation of images via a command line option. This option should specify a location for images. Currently, image location is the one of the trace file, which is always specified by the HTML/PHP interface.
- Revise the drawing of time streaks (the vertical blue lines). These should be adjusted to the (varying) tempo instead of the default metronomic setting.


Various issues
--------------

- Templates can't be created with rules containing integers as silences. This can be solved in MakeTemplate().
- Currently, the console crashes if the list of TEMPLATES in a grammar is not terminated with a solid line "-----". The interface takes care of this by adding the missing terminating line.
- Problem tracing the production of an item containing structural patterns.
- When outputing a data file of an item requiring serial tools (NeedZouleb > 0), display the result after the application of tools. Example: -gr.Visser.Waves. This may happen in Compute.c after SORTIR.
- Errors of duration occur when playing some polymetric structures with tied notes that miss their target. Examples are stored in -da.checkBadDurations.
- Check why tempo(3/2) {C4& {3,&C4 _rest D4}} does not produce the same pattern as {C4& {3,&C4 _rest D4}} 
- Check delete_orphan_ties() in data.php, as it still keeps erratic ties, which are difficult to predict.
- Check why istart=4 in Compute.c when running -gr.koto3. If not checked, it crashes on the remote right context of gram #2 rule #12. Therefore, if(istart > i) return(FALSE) has been added on 2025-03-15.
- Check that scripts can be attached to out-time objects
- In linux, when the STOP or PANIC button is clicked during a "wait" event, the trace file is empty. Maybe a problem flushing it and closing it.
- Check quadratic adjustment of _vel and _volume
